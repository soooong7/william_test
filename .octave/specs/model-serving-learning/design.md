# Model Serving 학습 사이트 설계

저장소에는 `README.md` 외에 애플리케이션 코드나 테스트가 없다. 기존 프레임워크·빌드 방식·UI 패턴을 따를 수 없으므로, 별도 서버와 인프라 없이 정적 파일을 열어 실행할 수 있는 브라우저 중심 구조를 선택한다. 설명과 시뮬레이션은 한국어를 기본으로 하고 `PyTorch`, `TensorFlow`, `Airflow` 같은 공식 기술명은 영문으로 병기한다. 실제 클러스터나 모델을 실행하지 않는다는 요구사항의 가정을 그대로 적용한다.

## 접근 방식

정적 HTML 한 장과 ES 모듈 JavaScript, CSS로 구현한다. 서버 라우팅이 필요하지 않도록 주제 이동은 URL hash(`#intro-model-serving`)를 사용한다. 콘텐츠는 렌더링 코드와 분리된 배열로 두어 12개 주제의 순서와 문구를 한 곳에서 검토할 수 있게 한다. 브라우저 기본 API만 사용하고 새 패키지나 외부 API는 도입하지 않는다.

### 파일 구성

- `index.html` — 사이트 제목, 학습 목록 영역, 진행 표시, 상세 콘텐츠 영역, 이전/다음/목록 이동 영역을 의미론적 HTML로 제공한다. JavaScript가 없어도 사이트의 목적과 오류 안내를 읽을 수 있는 기본 구조를 둔다.
- `styles.css` — 색상 토큰, 카드·코드·비교 영역, 반응형 레이아웃, 키보드 포커스 스타일을 정의한다. 320px부터 목록과 상세 영역이 한 열로 바뀌고 가로 오버플로를 만들지 않게 한다.
- `src/curriculum.js` — 요청된 순서의 12개 주제 데이터를 export한다. 각 항목은 고유 `slug`, 표시 제목, 학습 목표, 핵심 개념, 예시/흐름, 비교 관점, 요약 질문, 실행 여부(`simulation: true`)를 가진다. 프레임워크 3개 항목은 동일한 `input → runtime/model → output` 구조의 예시 데이터를 사용한다.
- `src/progress.js` — `localStorage`의 한 키에 완료 slug 목록과 마지막 slug를 저장하고 읽는다. 배열이 아니거나 12개 목록에 없는 값이 들어오면 삭제 후 빈 상태를 반환하며 저장 실패도 학습 화면을 중단시키지 않는다.
- `src/app.js` — hash를 읽어 주제를 선택하고, 목록·상세·진행률·이동 버튼을 렌더링한다. 알 수 없는 slug는 목록과 안내 메시지로 되돌린다. 완료 버튼은 진행 저장 후 목록과 진행 표시를 다시 렌더링하며, hash 변경·새로고침 시 마지막 주제를 복원한다.
- `tests/curriculum.test.js` — Node 내장 테스트 러너로 12개 항목의 개수, 순서, 고유 slug, 필수 콘텐츠 필드와 정확한 기술명 표기를 검증한다.
- `tests/progress.test.js` — 메모리 저장소를 주입해 완료/마지막 주제 저장, 새로 읽기, 손상된 값·알 수 없는 slug의 초기화, 저장소 오류의 안전한 처리를 검증한다.

## 콘텐츠와 화면 동작

목록에는 1부터 12까지의 번호, 제목, 완료 표시가 보인다. 상세 화면 상단에는 `현재 번호 / 12`, 제목, 학습 목표를 표시하고, 본문에는 핵심 개념·구체적 흐름·적용 시 고려할 점을 배치한다. 코드나 흐름은 실행 결과가 아니라 설명용 시뮬레이션임을 해당 블록에 명시한다. 하단에는 요약 질문과 완료 표시 버튼, 이전·다음·전체 목록 버튼을 둔다.

`#`에 slug가 없으면 저장된 마지막 slug를 우선 사용하고, 저장값도 없으면 첫 주제를 연다. slug가 유효하지 않으면 오류 안내, 전체 목록으로 돌아가는 링크, 첫 주제 링크를 보여준다. 콘텐츠 렌더링 중 개별 항목이 비정상이면 전체 앱을 덮어쓰지 않고 상세 영역에 오류 안내를 표시한다. 진행 저장이 불가능한 브라우저에서도 현재 화면의 완료 상태는 즉시 갱신하고, 영속 저장이 불가능하다는 안내만 제공한다.

## 데이터와 오류 처리

진행 데이터의 논리적 형태는 다음과 같다.

```json
{
  "completed": ["intro-model-serving"],
  "last": "intro-model-serving"
}
```

`completed`는 현재 커리큘럼에 존재하는 slug만 유지하고, `last`가 유효하지 않으면 첫 주제를 사용한다. 브라우저 저장소 접근 예외, JSON 파싱 실패, 누락된 필드는 빈 진행 상태로 처리한다. 서버·로그인·동기화·모델 파일은 사용하지 않으므로 마이그레이션은 없다.

## 테스트와 확인 방법

현재 저장소에는 테스트 프레임워크가 없으므로 새 의존성 없이 `node --test tests/*.test.js`로 순수 콘텐츠와 진행 상태 로직을 검증한다. 브라우저 전용 동작은 기존에 참고할 자동화 패턴이 없으므로 정적 서버 또는 파일 브라우저에서 다음 수동 확인을 수행한다.

- 목록과 각 상세 화면에 12개 주제와 필수 기술명이 표시되고, 목록 순서와 직접 이동이 일치하는지 확인한다.
- 각 상세 화면에서 학습 목표·설명·예시·요약 질문, 시뮬레이션 표기, 현재 번호, 이전·다음·목록 이동을 확인한다.
- 완료 표시, 진행률, 새로고침 후 마지막 주제 복원, 손상된 저장값 초기화, 잘못된 hash의 안내 화면을 확인한다.
- 320px 뷰포트와 데스크톱에서 가로 스크롤 없이 확인하고, Tab 키만으로 목록·이동·완료 버튼을 사용하며 포커스가 보이는지 확인한다.
- 개발자 도구에서 콘텐츠 오류를 재현해도 목록과 오류 안내가 남는지 확인한다.

UI 렌더링 자체를 자동 테스트할 기존 기반은 없으므로 위 브라우저 확인으로 검증한다. 추후 테스트 도구를 도입하기로 결정하면 `app.js`의 hash 선택·진행 계산을 순수 함수로 더 분리해 자동화 범위를 넓힐 수 있지만, 이번 간단한 정적 사이트에서는 별도 도구 추가를 넘겨두지 않는다.

## Decisions

- 서버 프레임워크 대신 정적 HTML/ES 모듈을 사용한다 — 현재 코드가 없고 실제 KServe·vLLM 실행이 범위 밖이므로 설치·배포 복잡도를 만들지 않는다.
- URL은 서버 경로 대신 hash를 사용한다 — 정적 호스팅에서 새로고침 시 404가 나는 문제를 피하면서 주제별 링크와 잘못된 주제 처리를 제공할 수 있다.
- 진행 상태는 브라우저 `localStorage`에 저장한다 — 계정·서버 동기화가 범위 밖이고, 새로고침 후 이어보기라는 요구를 충족하는 가장 작은 저장 방식이다.
- 콘텐츠와 렌더링을 분리한다 — 12개 주제의 정확성 검토와 향후 수정이 화면 로직 변경 없이 가능하다.
- 한국어 입문 수준과 브라우저 시뮬레이션을 채택한다 — 요청 언어와 “간단한 사이트”라는 목표에 맞고 실제 Python/Kubernetes 환경을 요구하지 않는다.

## Requirements Met

- 1.1 — `src/curriculum.js`의 12개 순서 데이터와 `index.html`/`src/app.js`의 목록·상세 렌더링이 모든 주제를 제공한다.
- 1.2 — 각 curriculum 항목의 목표·개념·예시·요약 질문 필드와 상세 화면 템플릿이 충족한다.
- 1.3 — curriculum 배열 순서, hash slug 직접 이동, 목록 렌더링이 충족한다.
- 1.4 — curriculum 콘텐츠와 `tests/curriculum.test.js`의 정확한 기술명 검증이 충족한다.
- 2.1 — 상세 상단의 번호 표시와 진행 표시가 충족한다.
- 2.2 — `src/app.js`의 이전·다음·전체 목록 컨트롤이 충족한다.
- 2.3 — 완료 버튼, `src/progress.js`, 목록 완료 표시와 진행률 갱신이 충족한다.
- 2.4 — localStorage의 `completed`/`last` 모델, 손상값 초기화, 저장 예외 처리가 충족한다.
- 2.5 — 알 수 없는 hash의 안내 화면과 목록 복귀 링크가 충족한다.
- 3.1 — curriculum의 비교 관점과 적용 고려 사항, 상세의 비교 영역이 서빙 방식 차이를 제공한다.
- 3.2 — 세 프레임워크 항목을 동일한 입력·런타임·출력 필드로 구성한다.
- 3.3 — Continuous Model Evaluation, 일반/Airflow 파이프라인, KServe, vLLM 항목에 역할과 고려 사항을 각각 기록한다.
- 3.4 — 모든 예시 항목의 `simulation` 표시와 상세 화면의 시뮬레이션 안내가 충족한다.
- 4.1 — `styles.css`의 320px 기준 단일 열 레이아웃과 오버플로 방지가 충족한다.
- 4.2 — 본문·코드·흐름·강조·요약 영역의 전용 스타일과 템플릿이 충족한다.
- 4.3 — 의미론적 버튼·링크, 키보드 순서, `:focus-visible` 스타일이 충족한다.
- 4.4 — 렌더링 오류를 상세 영역의 안내로 제한하고 목록 복귀 경로를 제공하는 `src/app.js`의 오류 처리가 충족한다.
