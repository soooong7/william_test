# Model Serving 학습 사이트 요구사항

현재 저장소에는 `README.md`만 있으며 애플리케이션 코드, 페이지 구조, 콘텐츠, 테스트 또는 기존 학습 기능이 없다. 따라서 이 작업은 AIOps 학습자가 브라우저에서 Model Serving의 핵심 개념과 패턴을 순서대로 학습할 수 있는 작은 교육용 사이트를 새로 정의하는 것이다. 사용자가 제시한 12개 주제를 하나의 학습 흐름으로 묶고, 각 주제의 개념·예시·확인 활동을 통해 단순한 용어 나열을 넘어 다음 학습으로 이어지게 하는 것이 목적이다.

## Requirements

### Requirement 1
사이트는 Model Serving을 기초 개념부터 전용 도구까지 학습할 수 있는 12개 주제의 커리큘럼을 제공해야 한다.

#### Acceptance Criteria
1. 학습 목록과 각 주제의 상세 화면에서 다음 12개 항목이 빠짐없이 식별 가능하다: Introducing Model Serving, Introducing Model Serving Patterns, Application 내 추론 런타임(Scikit-learn), Application 내 추론 런타임(PyTorch), Application 내 추론 런타임(TensorFlow), Continuous Model Evaluation, 배치 학습 및 서빙, 파이프라인 모델 서빙(일반 및 Airflow), Ensemble Model Serving Pattern, Business Logic Pattern, 전용 Serving 도구(KServe), 전용 Serving 도구(vLLM).
2. 각 주제에는 학습 목표, 핵심 개념 설명, 최소 하나의 구체적인 예시 또는 흐름 설명, 학습 완료를 확인할 수 있는 요약 또는 질문이 있다.
3. 커리큘럼의 표시 순서는 위 12개 항목의 순서를 기본으로 하며, 사용자는 목록에서 원하는 주제로 직접 이동할 수 있다.
4. 오탈자나 용어 혼동으로 인해 `Business Logic`, `PyTorch`, `TensorFlow`, `Airflow`가 다른 기술 또는 다른 주제로 표시되지 않는다.

### Requirement 2
학습자는 사이트 안에서 현재 위치와 학습 진행 상태를 이해하고 중단한 학습을 이어갈 수 있어야 한다.

#### Acceptance Criteria
1. 화면에서 현재 선택한 주제와 전체 12개 중 몇 번째인지 확인할 수 있다.
2. 이전 주제, 다음 주제, 전체 목록으로 이동하는 방법이 각 상세 화면에 제공된다.
3. 학습자가 주제의 완료를 표시하면 목록과 진행 표시에서 해당 상태가 반영된다.
4. 새로고침 후에도 완료 표시와 마지막으로 학습한 주제가 유지되며, 저장 데이터가 없거나 손상된 경우 사이트는 빈 진행 상태로 안전하게 시작한다.
5. 존재하지 않는 주제 주소로 접근해도 빈 화면이나 오류 화면 대신 유효한 학습 목록 또는 안내 화면이 표시된다.

### Requirement 3
사이트는 각 서빙 방식의 차이와 실제 적용 맥락을 비교해 이해할 수 있게 해야 한다.

#### Acceptance Criteria
1. 애플리케이션 내 추론 런타임, 배치 서빙, 파이프라인 서빙, 앙상블, 비즈니스 로직, KServe, vLLM을 서로 구분하는 설명 또는 비교가 제공된다.
2. Scikit-learn, PyTorch, TensorFlow 예시는 입력부터 추론 결과까지의 흐름을 보여주고, 세 프레임워크를 같은 기준으로 비교할 수 있다.
3. Continuous Model Evaluation, 파이프라인 일반/Airflow, KServe, vLLM을 설명할 때 각각의 역할과 사용 시 고려할 점이 포함된다.
4. 실행되지 않는 예시나 시각화가 있는 경우 실제 운영 환경에서 실행되는 기능인 것처럼 표시하지 않고, 예시·시뮬레이션임을 사용자에게 알린다.

### Requirement 4
학습 사이트는 데스크톱과 모바일 브라우저에서 기본적인 읽기와 탐색이 가능해야 한다.

#### Acceptance Criteria
1. 320px 이상의 화면 너비에서 가로 스크롤 없이 학습 목록, 본문, 이동 컨트롤을 사용할 수 있다.
2. 본문과 코드·다이어그램·강조 영역의 구분이 시각적으로 명확하고, 각 주제의 핵심 요약을 찾을 수 있다.
3. 키보드만으로 학습 목록, 주제 이동, 완료 표시를 사용할 수 있으며 포커스 위치가 보인다.
4. 콘텐츠 로딩 또는 렌더링에 실패한 주제는 전체 사이트를 중단시키지 않고 오류 안내와 목록으로 돌아가는 경로를 제공한다.

## Out of Scope

- 실제 Kubernetes 클러스터, KServe, vLLM, Airflow 또는 GPU 환경을 설치하거나 운영하는 기능
- 사용자의 모델을 업로드해 실제 추론·학습·배포하는 서비스
- 로그인, 다중 사용자 계정, 서버 기반 학습 이력 동기화
- 12개 주제 외의 전체 MLOps/AIOps 강의 과정이나 인증서 기능
- 외부 API 호출에 의존하는 실시간 모델 평가 또는 운영 모니터링

## Decisions for You

- 학습 콘텐츠의 실행 범위 — 브라우저에서 동작하는 설명·코드·시뮬레이션 중심(추천: 별도 인프라 없이 바로 학습할 수 있고 현재 저장소에 앱이 없기 때문)과 실제 Python/Kubernetes 실행 환경 중 선택. 기본 요구사항은 브라우저 중심의 시뮬레이션을 가정한다.
- 콘텐츠 언어와 깊이 — 한국어 설명에 필요한 영문 기술 용어를 병기하고 주제당 입문 수준으로 제공(추천: 요청이 한국어이고 “간단한 사이트”이기 때문)하거나, 영어 병행 또는 심화 실습까지 포함할지 결정. 기본 요구사항은 한국어 입문 수준을 가정한다.
